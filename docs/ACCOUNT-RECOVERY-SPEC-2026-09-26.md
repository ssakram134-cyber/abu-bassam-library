# الحساب الشخصي واستعادة البيانات — قرار 2026-09-26

هذه المواصفة أحدث من أي وصف سابق لربط Google أو حساب المزامنة عند التعارض.

## الهدف
- يستطيع المستخدم إنشاء حساب شخصي أو تسجيل الدخول بعد تبديل الهاتف أو الفورمات.
- الحساب هو هوية الشخص؛ Device ID هو هوية الفرع/الهاتف المنطقي. لا يجوز الخلط بينهما.
- تسجيل الدخول وحده لا يكسر عزل الفروع. استعادة هوية الجهاز الرئيسي تحتاج رمز استرداد طوارئ إضافيًا.

## إنشاء الحساب
الحقول الإلزامية: الاسم الكامل، اسم المستخدم، البريد الإلكتروني، كلمة المرور، إعادة كلمة المرور. الصورة الشخصية اختيارية ويمكن إضافتها أو تغييرها بعد تسجيل الدخول.

قواعد كلمة المرور: 12–128 محرفًا، حرف واحد على الأقل، رقم واحد على الأقل، رمز خاص واحد على الأقل، ومنع الكلمات الشائعة والتسلسلات السهلة وأسماء التطبيق/الحساب. لا تُحفظ كلمة المرور كنص داخل المشروع أو قاعدة البيانات الخاصة بالتطبيق.

اسم المستخدم: 3–32 محرفًا، حروف/أرقام و `_ . -` بدون مسافات، وفريد على مستوى الحسابات. تسجيل الدخول الأساسي بالبريد الموثق أو Google؛ اسم المستخدم للهوية داخل التطبيق وليس بديلًا عن البريد لتجنب كشف عناوين البريد.

## الملف الشخصي
- الاسم الكامل واسم المستخدم وصورة شخصية خاصة.
- البريد يؤخذ من Supabase Auth ولا ينسخ إلى جدول الملف الشخصي.
- صورة الحساب تحفظ في private Storage تحت مسار المستخدم `${auth.uid()}/profile/`.
- جدول `abu_bassam_profiles` يستخدم RLS ولا يستطيع المستخدم قراءة ملف شخص آخر.

## استعادة كلمة المرور
- زر «نسيت كلمة المرور» يرسل رابط استرداد إلى البريد بواسطة Supabase Auth.
- التطبيق يستخدم PKCE وDeep Link `abu-bassam-library://auth/callback`.
- بعد فتح رابط الاسترداد يعود المستخدم للتطبيق ويُطلب منه إدخال كلمة مرور قوية مرتين.

## Google
- زر «تسجيل الدخول بواسطة Google» يستخدم Supabase Auth OAuth/PKCE.
- Google هنا لإثبات الهوية فقط، ولا يطلب التطبيق صلاحية شاملة على Google Drive.
- لا تُخزن كلمة مرور Google داخل التطبيق.
- إضافة Google Drive كوجهة نسخ ثانية — إن اعتمدت لاحقًا — تكون منفصلة واختيارية وبأقل Scope ممكن مثل `drive.file`، ولا تكون شرطًا لتسجيل الدخول.
- يلزم تمكين Google Provider وإضافة Redirect URI في إعدادات Supabase Auth قبل اعتباره جاهزًا ميدانيًا.

## استعادة الهاتف بعد الفورمات أو الاستبدال
- الجهاز الرئيسي يستطيع إنشاء رمز استرداد طوارئ عالي العشوائية.
- الخادم يخزن SHA-256 للرمز فقط، ولا يخزن الرمز الصريح.
- الرمز يجب حفظه خارج الهاتف: ورقة، مدير كلمات مرور، أو مكان موثوق.
- على الهاتف الجديد: يسجل المستخدم الدخول إلى نفس الحساب ثم يدخل رمز الاسترداد.
- الخادم يتحقق من الحساب + الرمز ثم يعيد للهاتف الجديد Device ID القديم نفسه ويستبدل Device Secret بسر جديد.
- بهذه الطريقة تبقى النسخ السحابية وملفات الفرع والمستمسكات مرتبطة بالهوية القديمة، ولا تنشأ نسخة فرع موازية.
- أي Device ID مؤقت أنشئ على الهاتف الجديد يزال إذا كان جهازًا فرعيًا.
- رمز الاسترداد Single-use: بعد نجاح الاستعادة يصدر رمز جديد ويصبح القديم غير صالح.
- بعد 8 محاولات خاطئة يقفل الاسترداد 30 دقيقة.
- لا تنفذ استعادة هوية جهاز قديم إذا كان الأرشيف المحلي للهاتف الجديد يحتوي ملفات؛ يجب حفظها/تصديرها أولًا لمنع اختلاط الفروع.

## النسخ الاحتياطي
الحساب الشخصي لا يحل محل Backup Center. عند تسجيل الدخول يستمر النسخ السحابي Snapshot والمزامنة كلٌ بوظيفته. من صفحة الحساب يمكن بدء نسخة سحابية يدويًا ورؤية آخر نسخة ناجحة.

## قيود قبول الإصدار
- يحتاج تحقق ميداني: إنشاء حساب حقيقي، تأكيد البريد، Reset Password، صورة الحساب، الخروج/الدخول، الفورمات/هاتف ثانٍ، رمز الاسترداد، واستعادة Snapshot قديم.
- Google يحتاج إعداد Provider/Redirect في لوحة Supabase قبل الاختبار الفعلي.
- Leaked Password Protection يجب تفعيله من Supabase Auth Dashboard إذا بقي Security Advisor يحذر منه.

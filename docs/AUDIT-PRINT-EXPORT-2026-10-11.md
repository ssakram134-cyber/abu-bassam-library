# تدقيق الطباعة والتصدير — 11 أكتوبر 2026

## نطاق هذه الدفعة

بدأت المراجعة من ملفات إعدادات الطباعة وتصدير PDF ومسار الطباعة في Android، وراجعت المسارات المتصلة بها في واجهة الصور وقسم الأسئلة والبطاقات والهوية الوطنية. جرى فحص المصدر الفعلي من فرع `integration/library-sections-permissions-20261011`، وتعديل ثلاث وحدات تنفيذية أساسًا؛ هذا **تدقيق محدد النطاق، وليس إقرارًا بخلو جميع محركات الطباعة من الأخطاء**.

### ملفات التنفيذ التي عدلتها

| الملف | المشكلة المؤكدة | التصحيح |
|---|---|---|
| `web/print-presets-runtime.js` | يفترض نجاح الكتابة في LocalStorage؛ يؤدي فشل الكتابة إلى عرض قيمة معدلة في ذاكرة التشغيل رغم عدم حفظها | أصبحت عمليتا الإضافة والحذف لا تعتمدان التغيير إلا بعد نجاح الكتابة، مع إبلاغ المستخدم عند الفشل |
| `index.js` | عدم تنظيف PDF المؤقت عندما يلغي المستخدم اختيار المجلد أو يفشل الحفظ | تنظيف مؤقت PDF داخل `finally`، وعدم قراءة الملف المشفر إلا بعد منح إذن المجلد |
| `index.js` | تمرير صفحات غير متحققة ومقاسات `CUSTOM` غير منضبطة إلى HTML الخاص بالطباعة | حد 20 صفحة، حد 16MB لكل صورة و80MB للدفعة، مصدر صور PNG/JPEG/WebP محلي فقط، وقيم CUSTOM بين 50 و500 مم |
| `web/productivity-tools-runtime.js` | واجهة الأسئلة تعلن نجاح PDF قبل اختيار موقع حفظه | عرض حالة «طلب حفظ» بدل نجاح نهائي؛ الإقرار الحقيقي يصدر من Android عند انتهاء الكتابة |

### اختبارات رجوعية جديدة

1. `tools/check_print_presets_atomic.js`: تعطل الكتابة المحلية، تراجع إضافة/حذف الإعداد، نجاح كتابة مقاس جديد.
2. `tools/check_android_print_pdf_lifecycle.js`: تنظيف ملف PDF المؤقت بعد الإلغاء والنجاح وفشل كتابة PDF.
3. `tools/check_android_print_pages_safety.js`: محاذاة 297×210 ملم، الحد الأقصى للدفعة، رفض رابط صورة خارجي أو SVG أو مدخل يكسر خاصية HTML أو مقاس ضخم.

نجحت **محاكاة JavaScript/V8 معزولة** للاختبارات الثلاثة. أضيفت هذه الاختبارات إلى `package.json` فأصبح عدد أوامر `npm run check:web` المسجلة **68 أمرًا فريدًا**؛ تسجيل الأمر واختبار المحاكاة **ليس تشغيل المجموعة الكاملة داخل Node**.

## قيد مهم متعلق بإعدادات الطابعة

تُحفظ إعدادات *داخل التطبيق* مثل حجم الورق ونوع الوسيط وDPI وهوامش الصور والمقاسات المخصصة. اسم الطابعة داخل preset عبارة عن **تسمية للإعداد**، وليس ضمانًا بأن مربع حوار الطباعة في نظام Android سيختار تلك الطابعة تلقائيًا أو يُلزمها بدقة الطباعة. نظام الطباعة والسائق يتحكمان في خيارات الأجهزة الفعلية. يلزم اختبار تلك الإعدادات مع الطابعة المستخدمة قبل اعتماد تطابق المعاينة والطباعة.

## مسائل مفتوحة

- الطباعة الفعلية لبطاقة CR80 والوجه/الظهر، محاذاة A4 وA5، الصفحات متعددة الورق، جودة صور 300dpi، وإخراج PDF عبر طابعات Android المختلفة غير مثبتة على جهاز حقيقي.
- الاختبارات الرجوعية المضافة فحص جزئي؛ لم تُشغّل `npm ci` ولا `npm run check:web` بكامل اعتماداته، ولا بناء Expo/Gradle، ولا GitHub Actions.
- ضرورة التحقق من الأذونات الفعلية لاختيار المجلد ومنظومة Android للطباعة ومشكلات الذاكرة على جهاز منخفض الموارد.
- لم يُدمج شيء في `main`؛ التعديلات في طلب الدمج المسودة #92 فقط.

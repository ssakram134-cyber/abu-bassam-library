## 7 عيوب مثبتة في مراجعة مستقلة (تم إصلاح المصدر أو الاختبار)
1. **تعارض يمنع استيراد ZIP — حرج وظيفيًا:** `tools/validate_imported_source.js` كان يشترط `repair:source` ويحكم بالفشل عند غيابه، بينما `tools/check_android_workflow.js` يشترط ألا يوجد هذا الأمر في المشروع. حذفنا الشرط القديم واستبدلناه برفض صريح لإعادة إدخال أي أمر إصلاح مصدر تلقائي.
2. **مهلة غير شاملة لتنزيل ملفات OCR — متوسط:** `fetchWithTimeout` كان يلغي المؤقت بعد وصول HTTP headers، قبل `response.arrayBuffer()`. بقيت المهلة فعالة حتى استهلاك جسم الاستجابة كاملًا، مع إلغاء حقيقي عند التعليق.
3. **ملف OCR قد يبقى جزئيًا عند فشل الكتابة — متوسط:** كان التنزيل يكتب مباشرة إلى الاسم النهائي. أصبحت الكتابة إلى `.partial-<pid>` ثم `rename` ذرية، مع تنظيف المؤقت وإعادة المحاولة عند ENOSPC.
4. **فحص APK مضلل — متوسط:** كان `verifyBundle` يبحث عن سلسلة `assets/index.android.bundle` داخل بايتات APK بأي موضع. أصبح يقرأ ZIP central directory وlocal entry، ويتأكد من وجود ملف JS حقيقي بحجم أكبر من 1000 بايت ويمكن استخراج محتواه، ويرفض الأرشيف المكسور أو الاسم المزيف.
5. **فحص Android يفشل كذبًا — صغير لكنه يمنع اعتماد التغييرات:** كان يتطلب رسالة watchdog عربية قديمة رغم وجود نص فشل أكثر وضوحًا بالفعل في `index.js`. ربطنا الاختبار برسالة اليوم وأكّدنا تشغيل `setStartupFailed(true)` وزر إعادة المحاولة دون فك الحماية.
6. **عدم التحقق من CRC-32 لمحتوى JavaScript داخل APK — متوسط:** كان يمكن لملف متضرر بنفس الحجم أن ينجح؛ أصبح كود `verifyBundle` يفحص CRC-32 مقابل ZIP central directory، ويتقيد بحد 64MiB للتفكيك لتجنب التوسع غير المحدود. CRC يكشف التلف العرضي ولا يغني عن تحقق توقيع APK.
7. **اختيار APK غير حتمي مع وجود مخرجات متعددة — متوسط:** كانت `findApk` تعيد أول ملف APK تعثر عليه. الآن تفحص كل المرشحين داخل مجلد release وترفض وجود أكثر من APK، كي لا يُوزَّع ملف خاطئ.

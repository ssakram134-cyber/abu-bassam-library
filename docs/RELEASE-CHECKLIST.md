# قائمة فحص إصدار Android — 4.3.2 / build 432

## فحص آلي إلزامي
- `npm ci --no-audit --no-fund` باستخدام `package-lock.json` الحالي.
- `npm run check:web` ويشمل فحص المشروع والأمان وأحدث الميزات ومسار Android ومصادر OCR و`tools/check_backup_center.js` و`tools/check_account_center.js` و`tools/check_app_update.js` و`tools/check_legacy_security_debt.js`.
- إنشاء Android: `npm run android:prebuild`.
- بناء APK بنجاح عبر `assembleRelease`.
- التأكد من وجود `assets/index.android.bundle` داخل APK.
- التحقق من توقيع APK وشهادة الموقع بواسطة `apksigner`.
- إنشاء `SHA256.txt` و`SIGNING_CERTIFICATE.txt` و`BUILD_TYPE.txt`.
- رفع Artifact بنجاح.

## نوع البناء والتوقيع
- البناء بدون GitHub Release Secrets مسموح للاختبار فقط، ويجب أن يحمل `BUILD_TYPE.txt` القيمة:
  `test-release-default-key-with-embedded-js-NOT-FOR-PRODUCTION-UPDATES`
- لا تعتمد APK التجريبي كتحديث للمستخدمين ولا تعتبره Release إنتاجيًا.
- للإصدار الإنتاجي من GitHub Actions شغّل Workflow يدويًا واختر `production = true`.
- عند طلب Production يجب أن تكون الأسرار الأربعة موجودة: `ANDROID_KEYSTORE_BASE64` و`ANDROID_KEYSTORE_PASSWORD` و`ANDROID_KEY_ALIAS` و`ANDROID_KEY_PASSWORD`.
- النسخة الإنتاجية المقبولة يجب أن يحمل `BUILD_TYPE.txt` القيمة:
  `signed-production-release-with-embedded-js`
- يجب أن يكون مفتاح التوقيع هو نفس مفتاح الإصدارات السابقة حتى يقبل Android التحديث فوق النسخة المثبتة.

- يحتاج تحقق 🔍 تأكيد البريد من الرسالة وعودة Deep Link إلى التطبيق وبقاء الجلسة صحيحة.
- يحتاج تحقق 🔍 تسجيل الخروج ثم تسجيل الدخول بنفس الحساب واستمرار ظهور الملف الشخصي.
- يحتاج تحقق 🔍 رفع صورة شخصية وتغييرها والتأكد أن مستخدمًا آخر لا يستطيع قراءتها مباشرة.
- يحتاج تحقق 🔍 زر «نسيت كلمة المرور»، فتح رسالة الاستعادة، تعيين كلمة مرور جديدة قوية مرتين، ثم الدخول بها.
- يحتاج تحقق 🔍 تغيير كلمة المرور من الإعدادات للحساب المسجل حاليًا، لا بريد ثابت داخل الكود.
- يحتاج تحقق 🔍 إنشاء رمز استرداد هاتف من الجهاز الرئيسي، وحفظه خارج الهاتف، والتأكد أن الخادم لا يخزن الرمز الصريح.
- يحتاج تحقق 🔍 على هاتف ثانٍ/بعد فورمات: تسجيل الدخول إلى الحساب نفسه ثم استخدام رمز الاسترداد واستعادة Device ID القديم مع Device Secret جديد.
- يحتاج تحقق 🔍 التأكد أن SecureStore يثبت Device Secret الجديد أولًا، وبعدها فقط يصدر رمز استرداد جديد ويصبح القديم غير صالح.
- يحتاج تحقق 🔍 قطع التطبيق أو محاكاة فشل التخزين بين تحديث الخادم وتثبيت Device Secret والتأكد أن رمز الاسترداد الحالي يبقى صالحًا لإعادة المحاولة بدل قفل الحساب.
- يحتاج تحقق 🔍 8 محاولات رمز خاطئ تؤدي إلى قفل مؤقت 30 دقيقة.
- يحتاج تحقق 🔍 بعد استعادة هوية الهاتف فتح سجل النسخ السحابية القديمة واستعادة Snapshot قديم بنجاح.
- يحتاج تحقق 🔍 رفض استعادة هوية هاتف قديم إذا كان الأرشيف المحلي على الهاتف الجديد يحتوي ملفات، ومنع الاستعادة أيضًا إذا تعذر التحقق من حالة الأرشيف.
- يحتاج تحقق 🔍 تسجيل Google بعد تفعيل Provider وRedirect URL في Supabase، والتأكد أن OAuth يفتح خارجيًا وأن الصلاحيات المطلوبة للمصادقة فقط ولا تشمل وصولًا عامًا إلى Google Drive.

## اختبار النسخ الاحتياطي والاستعادة
- يحتاج تحقق 🔍 إنشاء Snapshot سحابي يدوي والتأكد من ظهوره بحالة Ready فقط بعد اكتمال كل الأجزاء.
- يحتاج تحقق 🔍 تعديل ملف ثم تشغيل النسخ التلقائي والتأكد من إنشاء Snapshot جديد عند وجود تغيير فقط.
- يحتاج تحقق 🔍 عدم إنشاء نسخة مكررة إذا لم تتغير البيانات.
- يحتاج تحقق 🔍 قطع الإنترنت أثناء الرفع والتأكد من عدم ظهور النسخة الناقصة ضمن النسخ القابلة للاستعادة.
- يحتاج تحقق 🔍 عودة الإنترنت ثم فتح التطبيق/إعادته للواجهة والتأكد من تنفيذ Catch-up تلقائي.
- يحتاج تحقق 🔍 استعادة Snapshot سحابي والتأكد من إنشاء `pre_restore` أولًا ثم فحص SHA-256 قبل الدمج.
- يحتاج تحقق 🔍 اختبار سياسة الاحتفاظ 3/7/14/30 والتأكد من إزالة النسخ الأقدم مع ملفاتها.
- يحتاج تحقق 🔍 اختبار فرعين فعليين والتأكد أن الفرع لا يستطيع قراءة أو استعادة Snapshot الفرع الآخر.
- يحتاج تحقق 🔍 اختبار Owner وعرض نسخ جميع الفروع دون كسر عزل الاستعادة على الجهاز الفرعي.
- يحتاج تحقق 🔍 إنشاء `.abuvault` مشفرة، استعادتها بكلمة مرور صحيحة، ورفض كلمة مرور خاطئة.
- ملاحظة إلزامية: النسخ السحابي التلقائي Catch-up يعمل عندما يكون Runtime التطبيق فعالًا؛ لا يُسجل كـAndroid background job بعد قتل التطبيق بالكامل.

- يحتاج تحقق 🔍 اختبار تحديث اختياري وتحديث إلزامي عبر `mandatory` و`min_supported_code`.

## قبول الإصدار
نجاح Build وحده لا يعد قبولًا ميدانيًا نهائيًا. المصدر والفحوص الآلية تسجل «تم ✅» عند نجاحها، أما الهاتف والطابعة والكاميرا والحساب والنسخ/الاستعادة والتحديث فتبقى «يحتاج تحقق 🔍» حتى التجربة الفعلية. ولا يعد أي APK إصدارًا إنتاجيًا ما لم ينجح التوقيع بالمفتاح المعتمد ويكون `BUILD_TYPE.txt` إنتاجيًا.

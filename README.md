## الأقسام
صوري والطباعة، البطاقة الوطنية والمستمسكات، **الباركود والكروت**، الحفظ والمستندات، صياغة الأسئلة، ضغط الصور، الإعدادات والأمان والسجل، الحساب وحماية البيانات، النسخ الاحتياطي، وتحديث التطبيق.

## الحساب الشخصي وحماية البيانات
من الإعدادات يوجد مركز حساب شخصي يدعم تسجيل الدخول، إنشاء حساب جديد، استعادة كلمة المرور، ملفًا شخصيًا باسم واسم مستخدم وصورة خاصة، وتسجيل Google عبر Supabase Auth. إنشاء الحساب يتطلب كلمة مرور قوية وتأكيدها مرتين. الحساب هو هوية الشخص، بينما Device ID يبقى هوية الفرع/الهاتف المنطقي؛ تسجيل الدخول وحده لا يلغي عزل الفروع. لاستعادة بيانات الجهاز الرئيسي بعد الفورمات أو تبديل الهاتف يوجد رمز استرداد طوارئ أحادي الاستخدام يعيد تبني Device ID القديم ويغيّر Device Secret، لذلك تبقى النسخ والملفات مرتبطة بهويتها الأصلية. التفاصيل الملزمة في `docs/ACCOUNT-RECOVERY-SPEC-2026-09-26.md`.

Google مخصص للمصادقة بالحد الأدنى من الصلاحيات ولا يمنح التطبيق وصولًا عامًا إلى Google Drive. أي تكامل Drive مستقبلي يجب أن يكون اختيارياً ومنفصلًا وبأقل Scope ممكن.

## الباركود والكروت
يحتوي أدوات التصميم المعتمدة: الباج التعريفي، الروضة/المدرسة، تسجيل الدخول/الإيميل، Wi‑Fi، QR، البطاقة التموينية، المواكب، الظرف، شهادات التقدير، كتاب الشكر. يوجد زر **🧩 النماذج** عام وزر نماذج خاص بكل قسم.

الأعداد: التعريفي 5، الروضة 10، تسجيل الدخول 10، Wi‑Fi 3، QR 4، **التموينية 10، المواكب 4، الأظرف 9، شهادات التقدير 10، الشكر 6**.

## صياغة الأسئلة
قسم مستقل للأسئلة فقط، عربي RTL / إنجليزي LTR، قوالب وأنواع أسئلة، A4/A5/مخصص، حفظ وطباعة/PDF. الظرف والشكر والشهادات ليست داخله. الأسئلة وضغط الصور Lazy-load.

## النسخ الاحتياطي
الحفظ المحلي والمزامنة والنسخ الاحتياطي ثلاث وظائف منفصلة. يوجد ZIP يدوي، نسخة يدوية مشفرة `.abuvault`، ومركز Snapshot سحابي تلقائي حسب الفرع مع SHA-256، تقسيم 5MB، حالة pending/ready، سياسة احتفاظ 3/7/14/30، وSnapshot أمان قبل الاستعادة. النسخ التلقائي يعمل عند تشغيل التطبيق/عودته للواجهة/عودة الإنترنت؛ لا يُوصف كـAndroid background job بعد قتل التطبيق بالكامل. التفاصيل الملزمة في `docs/BACKUP-CENTER-SPEC-2026-09-26.md`.

## تحديث التطبيق
من الإعدادات يوجد مركز فحص تحديثات Android. Metadata الإصدار لا تُقرأ مباشرة من الجدول، بل عبر Edge Function محمية بـJWT. APK يبقى في Storage خاص، وعند نشر تحديث حقيقي يحصل المستخدم على رابط تنزيل موقّع قصير العمر؛ لا يوجد GitHub Token داخل APK ولا تثبيت صامت. الإصدار 4.3.2/build 432 مسجل حاليًا كالإصدار المستقر، ولا يظهر تنزيل حتى يُرفع APK إنتاجي موقع ويُسجل SHA-256 وبصمة شهادة التوقيع. التفاصيل الملزمة في `docs/APP-UPDATE-SPEC-2026-09-27.md`.

نشر تحديث جديد لا يتم من APK اختبار. المسار المعتمد هو: بناء إنتاجي بواسطة `npm run build:apk:release`، ثم تمرير `SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY` كمتغيرات بيئة وتشغيل `npm run publish:update`. الناشر يثبت `BUILD_TYPE`، يعيد حساب SHA-256، يطابق شهادة التوقيع مع `config/release-signing-certificate.sha256`، يرفع APK إلى Storage الخاص، يعيد تنزيله للتحقق من الحجم والـSHA، ثم يفعّل Metadata ذريًا. الخادم يرفض VersionCode أقدم أو شهادة توقيع مختلفة.

## الأمان وبدء التشغيل
Splash watchdog على الويب وWebView، حقول الدخول LTR، منع المحاولة المكررة من ضغطة واحدة، عدم احتساب أخطاء الجهاز ككلمة مرور، SecureStore والبصمة وإدارة الأجهزة مفعلة. WebView يستخدم ملفات التطبيق المحلية فقط داخله، وروابط المصادقة الخارجية تفتح عبر النظام وتعود إلى Deep Link خاص بالتطبيق. أي مفاتيح توافق قديمة من نوع `__dev_secure_*` تُمسح وتُحجب مركزيًا، والعمليات الحساسة تفشل مغلقة إذا لم يتوفر SecureStore الأصلي.

## البناء
```bash
npm ci --no-audit --no-fund
npm run check:web
npm run android:prebuild
cd android
./gradlew assembleRelease --no-daemon
```

للبناء الإنتاجي الصارم والنشر الآمن:
```bash
npm run build:apk:release
npm run publish:update
```

GitHub Actions يبني Release standalone ويؤكد وجود `assets/index.android.bundle` والتوقيع، ويولد SHA-256. الـworkflow read-only ولا ينشئ commits تلقائيًا. الـAPK الناتج يبقى Artifact لمدة 14 يومًا ولا يُحفظ داخل شجرة المشروع.

نجاح CI لا يغني عن اختبار الهاتف والطابعة والكاميرا وQR والنسخ/الاستعادة الفعلية ومسارات الحساب والبريد وGoogle والتحديث على هاتف حقيقي.
